# Поиск на чертежах условных обозначений из заданного набора

Командный проект: модели и алгоритмы для точной детекции графических условных обозначений, заданных
набором геометрических шаблонов, на чертежах в векторном формате (DWG, PDF, SVG).
Полная постановка — [docs/task.md](docs/task.md).

В репозитории есть веб-сервис, на котором удобно готовить образцы и проверять алгоритм: он загружает
чертежи, показывает их с масштабом, позволяет обвести условное обозначение рамкой, сохранить его в
библиотеку и запустить поиск. **Алгоритма поиска пока нет** — вместо него работает заглушка.

## Что умеет сервис

| Раздел | Состояние |
|---|---|
| Чертежи | ✅ загрузка, список с миниатюрами, скачивание, удаление, повторная обработка |
| Просмотр чертежа | ✅ масштаб колесом, «Рука», листы, выделение рамкой, превью, точные координаты |
| Библиотека обозначений | ✅ сохранение образцов, переименование, категории, удаление · 🚧 импорт набора, экспорт датасета |
| Поиск | ✅ по выделенному фрагменту, по образцам из библиотеки, пакетный, история запусков · 🚧 **сам алгоритм** (заглушка находит только сам образец) |
| Оценка качества | 🚧 страница-заглушка |
| Оформление | 🚧 временное, все цвета вынесены в CSS-переменные (`frontend/src/styles.css`) |

## Быстрый старт

Понадобятся Python 3.12+ и Node.js 20.19+ (или 22.12+).

**Бэкенд** (API на http://localhost:8000, документация — http://localhost:8000/docs):

```sh
cd backend
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
```

**Фронтенд** (http://localhost:5173, запросы `/api` уходят на бэкенд):

```sh
cd frontend
npm install
npm run dev
```

Оба сервера одной командой (после установки зависимостей, Linux и macOS): `./scripts/dev.sh`.

**Без режима разработки.** Если фронтенд собран (`npm run build` в `frontend/`), бэкенд раздаёт его сам:
достаточно одного `uvicorn app.main:app`, и всё приложение откроется на http://localhost:8000.

**Чем проверить.** Загрузите файлы из `samples/` на странице «Чертежи», откройте план, приблизьте
светильник колесом мыши и обведите его рамкой.

```
  app/main.py             сборка приложения; раздача собранного фронтенда
  app/models.py           модели данных (они же — формат JSON в data/)

  app/storage.py          хранилище на файлах
  app/converters.py       PDF / SVG / DXF / DWG → страницы SVG + миниатюры

    base.py               интерфейс Detector

  app/routers/            обработчики API
  tests/                  pytest

  src/pages/              страницы (по одной на пункт меню + просмотр чертежа)
  src/components/         DrawingViewer (просмотрщик), загрузка файлов, общие элементы
  src/api/                типы и клиент API
  src/styles.css          временное оформление
samples/                  тестовые чертежи и эталонная разметка
datasets/                 обучающие наборы данных
experiments/<ник>/        личные черновики участников
notebooks/                общие ноутбуки
report/                   отчёт о качестве, figures/ — графики
scripts/make_samples.py   генератор тестовых чертежей
scripts/dev.sh            запуск бэкенда и фронтенда вместе
data/                     загруженные чертежи, библиотека, история (создаётся сама, в git не попадает)
```

Как сервис устроен внутри и как подключить свой алгоритм — [docs/architecture.md](docs/architecture.md).

## Страницы

| Адрес | Что там |
|---|---|
| `/` | обзор, счётчики, состояние сервиса (алгоритм, конвертер DWG) |
| `/drawings` | загрузка и список чертежей |
| `/drawings/:id?page=N&run=ID&symbol=ID` | просмотр: лист N, результаты запуска ID, подсветка образца ID |
| `/symbols` | библиотека обозначений — «заданный набор» |
| `/search` | пакетный поиск по нескольким чертежам и история запусков |
| `/evaluation` | оценка качества (заглушка) |
| `/about` | о проекте, форматы, аналоги |

Горячие клавиши в просмотре: `R` — рамка, `H` — рука (или зажать пробел), колесо — масштаб,
`+`/`−`/`0` — приблизить, отдалить, показать лист целиком, `Esc` — снять выделение,
`PageUp`/`PageDown` — листы.

## Тестовые данные

`samples/` — план этажа с обозначениями электрооборудования (розетка, выключатель, светильник,
распаячная коробка), повёрнутыми под разными углами, плюс таблица условных обозначений и дуги дверей
в роли помех:

- `plan.svg` — лист 1;
- `plan-2pages.pdf` — листы 1 и 2;
- `plan.dxf` — лист 1, обозначения оформлены блоками;
- `ground_truth.json` — эталон: тип, рамка и угол каждого экземпляра на каждом листе
  (флаг `legend` отмечает экземпляры в таблице обозначений).

Пересоздать: `backend/.venv/bin/python scripts/make_samples.py`.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SYMSEARCH_DATA_DIR` | `data/` | где хранить чертежи, библиотеку и историю |
| `SYMSEARCH_DETECTOR` | `stub` | какой алгоритм использовать |
| `SYMSEARCH_MAX_UPLOAD_MB` | `100` | ограничение размера файла |
| `SYMSEARCH_FRONTEND_DIST` | `frontend/dist/` | откуда раздавать собранный фронтенд |
| `BACKEND_URL` | `http://127.0.0.1:8000` | куда Vite проксирует `/api` в режиме разработки |

## Командная работа

- Задачу делаем в ветке `<ник>/<кратко-что-делаю>`, в `main` попадаем через Pull Request.
- Личные черновики — в `experiments/<ник-на-github>/`, переиспользуемый код — в `backend/`.
- Перед Pull Request: `pytest`, а если менялся фронтенд — `npm run lint && npm run build`.
- Не коммитим `data/`, веса моделей и большие наборы данных — публикуем отдельно и даём ссылку.
- Правила для ИИ-ассистентов (Claude Code, Cursor, Codex, ChatGPT) — [AGENTS.md](AGENTS.md).
  Claude Code, Cursor и Codex подхватывают их сами; в ChatGPT вставьте `AGENTS.md` в начало диалога.
