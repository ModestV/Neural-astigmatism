# SymSpot

Поиск обозначений на чертеже по эталонам, размеченным на том же чертеже, с раскраской линий
найденных символов.

## Что делает SymSpot

На вход подаются чертеж (PDF, SVG, PNG или JPG) и список эталонов: рамки вокруг образцов
обозначений, обычно из легенды этого же листа. Для каждого эталона программа ищет на чертеже
все его экземпляры, допуская поворот, изменение масштаба в заданных пределах и зеркальное
отражение. Обучения нет: единственным источником знаний об обозначении служит сам эталон.

Результат состоит не из рамок, а из линий: каждому найденному экземпляру назначаются те куски
геометрии чертежа, которые принадлежат символу, и только они окрашиваются цветом класса. Если
через символ проходит стена или размерная линия, окрашивается лишь часть линии внутри символа.
Дополнительно записываются `result.json`, оверлеи в SVG, PDF и PNG и интерактивный HTML-отчет.

Основной вход векторный (PDF, SVG): геометрия читается напрямую, поиск опирается на точные
координаты штрихов и текст. Растровый вход (PNG, JPG) обрабатывается упрощенной веткой: скелет
линий, поиск по карте расстояний, та же проверка покрытия и маски пикселей вместо назначения
кусков.

## Установка

Нужны [uv](https://docs.astral.sh/uv/) и Python 3.11 (uv скачает нужную версию сам, версия
зафиксирована в `.python-version`).

```bash
git clone <адрес репозитория> && cd Neural-astigmatism
uv sync
```

Для растеризации SVG в PDF/PNG используется `cairosvg`, которому нужна системная библиотека
cairo:

```bash
brew install cairo          # macOS
sudo apt install libcairo2  # Debian/Ubuntu
```

На macOS путь Homebrew (`/opt/homebrew/lib`, `/usr/local/lib`) подхватывается автоматически,
переменные окружения задавать не нужно.

Проверка установки:

```bash
uv run symspot --help
uv run pytest -q
```

## Быстрый старт

Все команды выполняются из корня репозитория. Каталог `out/` в `.gitignore`.

**1. Сгенерировать синтетический чертеж** (один small, seed 0):

```bash
uv run python -m symspot.synth --n 1 --size small --seed 0 --out out/synth
# то же самое: uv run symspot synth --n 1 --size small --seed 0 --out out/synth
```

В `out/synth/` появятся `small_000.svg`, `small_000.pdf`, `small_000.png`,
`small_000_dirty.png` (шум, размытие, лишний наклон), `small_000_gt.json` (разметка: эталоны и
экземпляры) и `small_000_coco.json`, `small_000_dirty_coco.json` (то же в стиле COCO из CVAT).

**2. Запустить поиск на SVG**, взяв эталоны и разметку из `*_gt.json`:

```bash
uv run symspot run out/synth/small_000.svg \
  --queries out/synth/small_000_gt.json --gt out/synth/small_000_gt.json --out out/svg
```

Фрагмент вывода (16 классов, в таблице показаны не все строки):

```

┃ класс          ┃ экземпляров ┃ ambiguous ┃
│ bell           │           3 │         0 │
│ duplex         │           3 │         0 │
│ gfci           │           6 │         0 │
...
│ ВСЕГО          │          61 │         0 │
...
│ total     │  4.85 │
...
│ ИТОГО          │ 1.000 │ 1.000 │ 1.000 │ 61 │  0 │  0 │
similar_group_error: 0.000 (символов в группах: 38)
```

В каталоге `out/svg/` лежат `result.json`, `overlay.svg`, `overlay.pdf`, `overlay.png`,
`report.html`, `metrics.json`. Откройте отчет:

```bash
open out/svg/report.html        # macOS; на Linux: xdg-open
```

**3. То же на PDF:**

```bash
uv run symspot run out/synth/small_000.pdf \
  --queries out/synth/small_000_gt.json --gt out/synth/small_000_gt.json --out out/pdf
```

```
 small_000.pdf: найдено 61 (плюс 16 самих эталонов)
│ total     │  3.11 │
│ ИТОГО          │ 1.000 │ 1.000 │ 1.000 │ 61 │  0 │  0 │
```

**4. Метрики по готовому `result.json`:**

```bash
uv run symspot eval out/pdf/result.json out/synth/small_000_gt.json --out out/pdf/metrics2.json
```

Вывод: те же таблицы «Метрики по классам» и `similar_group_error`, итог
`ИТОГО 1.000 1.000 1.000 61 0 0`. Сопоставление предсказаний с разметкой идет по IoU рамок
(`--iou`, по умолчанию 0.5, венгерский алгоритм).

**5. Растр** (команды те же, чертежом служит PNG или JPG; эталоны в пикселях этого изображения
или с масштабированием, см. ниже):

```bash
uv run symspot run out/synth/small_000.png \
  --queries out/synth/small_000_coco.json --gt out/synth/small_000_coco.json --out out/png
```

В сводке: `найдено 54 (плюс 16 самих эталонов)`, метрики
`ИТОГО 0.963 0.852 0.904 52 2 9` (P, R, F1, tp, fp, fn), время около 35 с (основная часть:
chamfer-поиск гипотез). Для «грязного» изображения используются `small_000_dirty.png` и
`small_000_dirty_coco.json`.

**6. Демо в браузере:**

```bash
uv run streamlit run app/demo.py
```

Адрес по умолчанию `http://localhost:8501`. В боковой панели загрузка чертежа и файла
эталонов, номер страницы PDF, основные пороги, кнопка «Пример» (генерирует small-синтетику) и
кнопка «Найти»; в основной области оверлей, таблица экземпляров с фильтром по классу,
ambiguous, метрики (если в файле есть разметка экземпляров) и скачивание `overlay.svg`,
`overlay.pdf`, `result.json`, `report.html`. Подробности в `app/README.md`.

### Опции `symspot run`

| Опция | Назначение |
|---|---|
| `--queries` | файл эталонов (обязательно): COCO, простой JSON или GT синтетики |
| `--out` | каталог результата (обязательно) |
| `--config` | YAML с порогами (можно задать только часть полей) |
| `--set key=value` | переопределение поля конфига, повторяемая опция |
| `--page N` | номер страницы PDF, с нуля (по умолчанию 0) |
| `--formats` | какие файлы рисовать: `svg,pdf,png,html` (по умолчанию все); пустая строка оставляет только `result.json` |
| `--gt` | файл разметки экземпляров; включает подсчет метрик и запись `metrics.json` |
| `--iou` | порог IoU для метрик (0.5) |
| `-v` | подробный лог и трейсбеки вместо короткого сообщения об ошибке |

`symspot eval <result.json> <gt> [--iou] [--out metrics.json]` считает метрики по записанному
результату. `symspot synth` повторяет генератор (`--n`, `--size small|large`, `--seed`, `--out`,
`--no-raster`).

## Форматы входа

Тип файла эталонов определяется по содержимому. Во всех форматах `legend_id` задает класс
символа (строка), несколько рамок с одним `legend_id` допустимы: каждая становится отдельным
эталоном (вариантом) класса, это полезно, если обозначение на чертеже встречается в разных
начертаниях.

### COCO из CVAT

Используются аннотации двух категорий:

- `legend_item`: эталон. Класс берется из `attributes.legend_id`, подпись из
  `attributes.meaning` (необязательна);
- `object`: разметка экземпляров, нужна только для метрик (`--gt`, `symspot eval`, демо).

`bbox` в COCO имеет вид `[x, y, w, h]`. Если известен размер чертежа, а в `images[]` указаны
`width` и `height`, координаты умножаются на `W_чертежа / width` и `H_чертежа / height`
(например, COCO размечен на растеризации 300 dpi, а читается векторный PDF или SVG). Если в
файле несколько изображений, нужное выбирается по имени чертежа: сравниваются базовые имена
файлов без каталогов и без расширения (`sheet.pdf` совпадет с `sheet.jpg`); при нулевом или
неоднозначном совпадении выдается ошибка со списком имен из файла. Если изображение одно,
оно берется без сверки имени.

Пример (сокращенный, на синтетике изображение 2500x1667 при чертеже 600x400 pt):

```json
{
  "categories": [{"id": 1, "name": "legend_item"}, {"id": 2, "name": "object"}],
  "images": [{"id": 1, "width": 2500, "height": 1667, "file_name": "small_000.png"}],
  "annotations": [
    {"id": 1, "image_id": 1, "category_id": 1, "bbox": [2113.7, 128.1, 54.2, 54.2],
     "attributes": {"legend_id": "duplex", "meaning": "Duplex receptacle"}}
  ]
}
```

Прогон на SVG с таким файлом (`small_000_coco.json`) дал `ИТОГО 1.000 1.000 1.000 61 0 0`.

### Простой JSON

Только эталоны, рамка `[x0, y0, x1, y1]` в единицах чертежа (pt для PDF, единицы `viewBox` для
SVG, пиксели для растра). Допустимы две формы.

Список:

```json
[
  {"legend_id": "duplex", "bbox": [507.3, 30.75, 520.3, 43.75], "label": "Duplex receptacle"},
  {"legend_id": "gfci",   "bbox": [505.89, 55.19, 521.71, 64.31]},
  {"legend_id": "panel",  "bbox": [506.24, 324.57, 521.36, 334.93]}
]
```

Объект с размером исходного изображения (тогда координаты масштабируются к чертежу так же, как
в COCO; поле `image` информационное и не используется):

```json
{"width": 2592, "height": 1728,
 "legend_items": [{"legend_id": "A", "bbox": [1239.92, 178.88, 1324.8, 227.76], "label": "2x4 LED lay-in"}]}
```

Пример разметки реального листа лежит в `docs/real/camden_queries.json`. Если в `--queries`
передать только три класса из 16 (как в списке выше), `symspot run` на `small_000.svg` находит 13
экземпляров; классы, которых нет среди эталонов, не ищутся, а близкий по форме символ отсутствующего класса может
быть принят за присутствующий (в этом прогоне один `r220` получил метку `duplex`).

### GT синтетики

`<name>_gt.json` содержит `width`, `height`, `units`, `queries` (эталоны), `instances`
(экземпляры с `legend_id`, `T`, `bbox`, `path_ids`, `is_query`), `similar_groups` (группы
почти одинаковых классов для метрики `similar_group_error`). Один файл годится и как
`--queries`, и как `--gt`.

## Формат выхода

Каталог `--out`:

| Файл | Содержимое |
|---|---|
| `result.json` | все найденные экземпляры, эталоны, тайминги, использованный конфиг |
| `overlay.svg` | исходный чертеж серым (opacity 0.35) и цветной слой с точной геометрией назначенных кусков; ambiguous рисуются пунктиром |
| `overlay.pdf` | для PDF-источника копия страницы с цветными линиями поверх, иначе PDF из SVG-оверлея (cairosvg) |
| `overlay.png` | растровый оверлей |
| `report.html` | картинка с zoom/pan, таблица экземпляров, фильтр по классу, клик подсвечивает экземпляр, блок ambiguous |
| `metrics.json` | метрики (только если задан `--gt`) |

Цвет класса стабилен по `legend_id`. Какие оверлеи писать, задает `--formats`.

### result.json

Верхний уровень (`Result`):

| Поле | Смысл |
|---|---|
| `drawing` | путь к чертежу, как он был передан |
| `kind` | `vector` или `raster` |
| `width`, `height`, `page` | размер чертежа в единицах чертежа (pt, единицы `viewBox`, пиксели) и номер страницы |
| `queries` | использованные эталоны: `legend_id`, `bbox`, `label` (после масштабирования к чертежу) |
| `instances` | список экземпляров |
| `timings` | секунды по этапам (`read`, `normalize`, `index`, `query`, `pairs`, `exact`, `vote`, `verify`, `compete`, `assign`, `resolve`, `expand`, `total`; у растра свои этапы) |
| `config` | полный конфиг прогона (все пороги) |

Экземпляр (`Instance`):

| Поле | Смысл |
|---|---|
| `id` | порядковый номер в списке |
| `legend_id` | класс |
| `T` | подобие `{s, theta, tx, ty, mirror}`: переводит нормализованный эталон в координаты чертежа, `p' = s * R(theta) * M * p + (tx, ty)`, где `M = diag(1, -1)` при `mirror`. Нормализованный эталон: центр рамки в нуле, диагональ рамки равна 1, поэтому `s` равно диагонали экземпляра в единицах чертежа. Угол в радианах, ось Y вниз |
| `score` | оценка совпадения: взвешенное покрытие эталона минус небольшой штраф за лишнюю тушь внутри |
| `coverage` | доля сэмплов эталона, у которых на чертеже есть линия ближе допуска с согласованным направлением |
| `prim_coverage` | покрытие по каждому примитиву эталона |
| `piece_ids` | идентификаторы кусков планаризованного чертежа, назначенных экземпляру (по ним строится раскраска) |
| `parent_ids` | идентификаторы исходных подпутей файла, из которых получены эти куски |
| `bbox` | рамка `[x0, y0, x1, y1]` в единицах чертежа |
| `status` | `ok` или `ambiguous`: два класса претендуют на одно место и их score различаются меньше `compete_margin`; в отчет попадают оба, конкуренты перечислены в `rivals` |
| `rivals` | `legend_id` конкурентов при `ambiguous`, иначе пусто |
| `is_query` | экземпляр совпал с самим эталоном (образец в легенде); из метрик и сводки CLI исключается, но в оверлее и файле остается |
| `source` | откуда гипотеза: `exact` (точная копия), `vote` (голосование пар штрихов), `text` (совпадение текста), `expand` (расширение запроса), `chamfer` (растр) |
| `variant` | номер варианта эталона внутри класса (0 для исходного) |
| `residual` | средний остаток ICP в долях диагонали эталона |
| `mask_rle` | только растр, иначе `null`: маска пикселей экземпляра |

Формат `mask_rle` (`symspot/raster/mask.py`):
`{"origin": [x0, y0], "size": [h, w], "counts": [...]}`. Маска `h` на `w` пикселей лежит в
изображении начиная с пикселя `(x0, y0)`; `counts` это длины серий в порядке строк (row-major),
первая серия нулевых пикселей (может быть равна 0), затем серии единиц и нулей по очереди.
Пример декодирования:

```python
import json
from symspot.raster.mask import rle_decode

res = json.load(open("out/png/result.json"))
mask, (x0, y0) = rle_decode(res["instances"][0]["mask_rle"])  # bool (h, w)
```

Прочитать файл обратно можно через `symspot.core.types.Result.from_dict(...)`.

## Конфигурация

Все пороги заданы в `symspot/core/config.py` (pydantic-модель `Config`, неизвестное поле
вызывает ошибку) и продублированы в `configs/default.yaml`. Переопределение:

```bash
uv run symspot run drawing.svg --queries q.json --out out/ \
  --config my.yaml --set accept_score=0.7 --set allow_mirror=false
```

`my.yaml` может содержать любое подмножество полей, остальные берутся по умолчанию; `--set`
применяется поверх файла, значение разбирается как YAML (`false`, `0.7`, `3`).

| Поле | По умолчанию | Смысл и единицы |
|---|---|---|
| `sample_step` | 0.02 | шаг сэмплирования линий, доля диагонали эталона |
| `cover_tol` | 0.03 | допуск совпадения линии, доля диагонали эталона (плюс половина толщины линии) |
| `exact_tol` | 0.005 | допуск поиска точных копий, доля диагонали эталона |
| `query_parent_inside` | 0.8 | штрих попадает в эталон, если не менее этой доли его длины внутри рамки |
| `scale_min`, `scale_max` | 0.7, 1.4 | допустимый масштаб экземпляра относительно эталона |
| `allow_mirror` | true | искать зеркальные экземпляры (для эталонов с текстом зеркало не пробуется) |
| `pair_radius_factor` | 1.5 | радиус пар штрихов: множитель к максимальной диагонали эталонов и `scale_max` |
| `angle_bin_deg` | 5 | ячейка угла в аккумуляторе голосования, градусы |
| `scale_bin_log` | 0.05 | ячейка логарифма масштаба |
| `shift_bin` | 0.25 | ячейка сдвига, доля диагонали эталона |
| `min_distinct_pairs` | 3 | минимум разных пар эталона, давших голоса за гипотезу (ограничивается числом пар самого эталона) |
| `max_hypotheses_per_query` | 2000 | потолок гипотез на эталон |
| `icp_iters`, `icp_angle_deg` | 15, 20 | итерации ICP и допуск угла касательных, градусы |
| `min_prim_coverage` | 0.6 | минимальное покрытие каждого примитива эталона (иначе отказ) |
| `accept_score` | 0.8 | минимальный score для принятия экземпляра |
| `extra_ink_lambda` | 0.05 | вес штрафа за лишнюю тушь |
| `discriminative_weight` | 3.0 | вес сэмплов, отличающих эталон от похожего |
| `similar_cover` | 0.85 | эталоны считаются похожими, если один покрывает другой на эту долю |
| `compete_iou` | 0.5 | порог перекрытия рамок, с которого экземпляры разных классов соревнуются (считается как пересечение, деленное на площадь меньшей рамки) |
| `compete_margin` | 0.03 | минимальный отрыв победителя, иначе `ambiguous` |
| `assign_inside` | 0.7 | кусок отдается экземпляру, если не менее этой доли его сэмплов лежит ближе `cover_tol` к эталону |
| `resolve_taken_frac` | 0.5 | экземпляр отклоняется, если больше этой доли его кусков уже занято |
| `expand`, `expand_score` | true, 0.9 | расширение запроса уверенными экземплярами и порог их score |
| `flatten_tol`, `arc_fit_tol`, `merge_gap`, `snap_tol` | 0.002, 0.01, 0.005, 0.002 | допуски нормализации, доли опорного размера символа (медиана диагоналей рамок эталонов) |
| `raster_angle_step`, `raster_scale_step` | 10, 0.05 | шаг угла (градусы) и масштаба в растровом поиске |
| `raster_tile`, `raster_topk` | 2048, 200 | размер тайла и число гипотез на эталон (растр) |
| `sauvola_window`, `sauvola_k`, `min_blob_px`, `deskew` | 25, 0.2, 8, false | бинаризация и очистка растра |
| `raster_chamfer_max` | 0.08 | порог среднего chamfer для гипотезы, доля диагонали |
| `seed` | 0 | зерно |
| `workers` | auto | зарезервировано, в текущем коде не используется |

## Как это работает

Векторный конвейер (`symspot/pipeline.py`):

1. Чтение: PDF через PyMuPDF (линии, кривые, прямоугольники, текстовые фрагменты, поворот
   страницы), SVG через `svgelements` (все transform, `<use>`, `<text>`). Каждый исходный
   подпуть сохраняется как родитель.
2. Нормализация: кривые Безье в полилинии, окружность из четырех кривых и дуги в `Arc`,
   склейка коллинеарных отрезков, планаризация (разрез в точках пересечения, STRtree). Каждый
   кусок помнит исходный подпуть (`parent_id`) и штрих до разреза (`stroke_id`). Допуски
   задаются в долях размера символа.
3. Эталоны: из рамки берутся штрихи, не менее `query_parent_inside` длины которых лежит внутри
   (стена, проходящая через рамку, отбрасывается). Эталон нормализуется (центр в нуле,
   диагональ 1) и сэмплируется с касательными.
4. Точные копии (хеш по якорю) и голосование пар штрихов: пара штрихов эталона задает ключ,
   инвариантный к подобию (типы, отношение размеров, углы относительно линии между якорями).
   Совпавшие пары на чертеже голосуют за сдвиг, угол, масштаб и зеркало; гипотеза принимается
   при голосах от нескольких разных пар с учетом плотности линий. Для эталонов с текстом
   добавляются гипотезы по совпадению строки.
5. ICP и покрытие: гипотеза уточняется ICP по ближайшим сэмплам с согласованным направлением,
   затем считается взвешенное покрытие эталона и покрытие каждого его примитива.
6. Отличающие части и соревнование: у похожих эталонов (duplex, GFCI, 220; выключатели S, S3,
   SD) сэмплы, которых нет у соседа, получают повышенный вес. Экземпляры разных классов на
   одном месте сравниваются по score, при малом отрыве оба получают `ambiguous`.
7. Назначение кусков: экземпляру отдаются куски чертежа, лежащие вдоль трансформированного
   эталона.
8. Глобальное разрешение: классы идут по убыванию сложности (абсолютной длины линий и текста), куски достаются первому
   претенденту, экземпляры с большей частью уже занятых кусков отклоняются, дубли одного класса
   объединяются.
9. Расширение запроса: уверенные экземпляры, заметно отличающиеся от эталона, добавляются как
   варианты эталона, и поиск повторяется один раз по оставшимся кускам.

Растровая ветка (`symspot/raster/`): серое изображение, бинаризация Sauvola, удаление мелкого
мусора, скелет, карта расстояний и направлений. Эталоном служит скелет кропа из рамки. Гипотезы
дает chamfer-поиск: плотный проход по всем центрам на сильно уменьшенном растре, затем перебор
поз в лучших центрах и уточнение угла, масштаба и центра; затем та же проверка (ICP, покрытие,
соревнование), что и в векторной ветке, на точках скелета. Вместо назначения кусков для каждого
экземпляра строится маска пикселей туши, близких к трансформированному эталону и совпадающих с
ним по направлению градиента, она записывается как `mask_rle`. Разрешение конфликтов идет по
рамкам.

## Ограничения

- Нет обучаемой ветки (SymPoint под запрос, DINOv2, VLM-арбитр) и нейросетей вообще.
- Эталон должен быть на том же листе: поиск идет по образцам с этого же чертежа, словаря
  символов или предобученных классов нет.
- Растровая ветка упрощена: текст в растре не распознается (OCR нет), текстовая часть
  эталона по буквам не сверяется; сильная перспектива, фото и
  рукописные чертежи не поддерживаются, deskew по умолчанию выключен.
- DXF и PDF XObject не имеют отдельного быстрого пути: DXF не читается (нужно сначала
  экспортировать в PDF или SVG), PDF читается как набор путей.
- Символы без геометрии, состоящие из одного текста, ищутся только по совпадению строки.
  Зеркальные экземпляры эталонов с текстом не ищутся.
- Масштаб экземпляров ограничен `scale_min`..`scale_max` (по умолчанию 0.7-1.4 от эталона),
  сильно искаженные пропорции (аффинные, не подобные преобразования) не поддерживаются.
- Похожие символы различаются только если все они заданы эталонами: символ отсутствующего в
  легенде класса может получить метку присутствующего.
- Параллельной обработки по эталонам и тайлам нет: поле `workers` зарезервировано.
- Известные пропуски на синтетике: зеркальный символ, перекрытый стеной, и редкие потери в PDF
  (см. раздел «Результаты»).

## Разработка

```bash
uv run pytest -q                          # быстрые тесты (маркер bench отключен по умолчанию)
uv run pytest -m "not slow and not bench" -q   # без долгих тестов (large-синтетика и др.)
uv run pytest tests/bench -m bench -s     # бенчмарк фазы 6: large вектор и растр
uv run ruff check . && uv run ruff format --check .
```

Маркеры `slow` (долгие тесты на large-синтетике) и `bench` (бенчмарк, исключен через
`addopts = "-m 'not bench'"`) объявлены в `pyproject.toml`. На момент написания полный
`uv run pytest -q` дает 347 passed, `ruff` чист.

Структура пакета:

```
symspot/
  core/        types.py (контракты), config.py (все пороги), geometry_utils.py (подобие, Umeyama, сэмплинг)
  io/          pdf_reader.py, svg_reader.py, raster_reader.py, annotations.py (COCO, простой JSON, GT синтетики)
  normalize/   bezier.py (Безье, дуги), merge.py (склейка), planarize.py (разрез), index.py (STRtree, cKDTree)
  query/       extract.py (эталон из рамки), descriptors.py (якоря, ключи пар), discriminative.py (отличающие части)
  exact/       hashing.py (точные копии по хешу)
  search/      pairs.py (таблица пар), voting.py (голосование, NMS, текстовые гипотезы)
  verify/      icp.py (уточнение), coverage.py (покрытие, проверка), compete.py (соревнование, ambiguous)
  paint/       assign.py (назначение кусков экземпляру)
  resolve/     global_resolve.py (разрешение конфликтов за куски)
  expand/      query_expansion.py (расширение запроса)
  raster/      preprocess.py, chamfer.py, verify_raster.py, mask.py (RLE), pipeline.py
  render/      svg_overlay.py, pdf_overlay.py, png_overlay.py, html_report.py, palette.py
  synth/       symbols.py, layout.py, plan_generator.py, export.py (генератор синтетики)
  eval/        metrics.py (P/R/F1, confusion, ошибки в группах похожих)
  pipeline.py, cli.py
app/demo.py    Streamlit-демо
tests/         зеркалит пакет; tests/core_algo, tests/e2e, tests/bench
docs/          PLAN.md, PROGRESS.md, REPORT.md, real/camden_queries.json

```

Каталоги `src/`, `scripts/`, `notebooks/`, `experiments/`, `paper/` и часть `configs/`
остались от прежнего скелета репозитория, к пакету `symspot` они не относятся и исключены из
линтера.

Роли: архитектура, контракты, алгоритмическое ядро и ревью ведет главная сессия (Opus);
периферия и тесты делегируются сабагентам (`.claude/agents/`: `sonnet-implementer`,
`sonnet-tester`, `sonnet-viz`). План работ и правила делегирования в `docs/PLAN.md`, соглашения
(типы везде, пороги только в `core/config.py`, координаты в единицах чертежа с осью Y вниз,
`symspot/core/types.py` меняет только главная сессия) в `CLAUDE.md`, ход работ и принятые
решения в `docs/PROGRESS.md`.
