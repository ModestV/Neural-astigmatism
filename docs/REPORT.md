# SymSpot MVP: итоговый отчет

## 1. Что сделано

SymSpot находит на чертеже все вхождения обозначений, заданных эталонами (рамками
`legend_item`) с того же листа, и раскрашивает линии найденных символов. Обучения нет:
поиск геометрический (подобие с отражением), проверка по покрытию линий эталона.

- Вход: PDF и SVG (векторная ветка), PNG и JPG (растровая ветка); эталоны в COCO из CVAT,
  простом JSON или GT синтетики.
- Выход: `result.json`, оверлеи `overlay.svg`, `overlay.pdf`, `overlay.png`, интерактивный
  `report.html`; CLI `symspot run/eval/synth`; Streamlit-демо `app/demo.py`.

## 2. Метрики на синтетике

Генератор: 16 классов, в том числе группы почти одинаковых символов (duplex / GFCI / 220,
S / S3 / SD, ⊘ / круг с крестом, детекторы SD / CO); повороты на произвольный угол,
масштаб ±15 %, зеркало; сложные случаи: стена через символ, символ у штриховки, отрезки,
разбитые на куски, окружность из четырех кривых Безье. Сопоставление с разметкой по IoU
рамок >= 0.5 (венгерский алгоритм), эталоны легенды из метрик исключены.

| Набор | F1 | Precision | Recall | Ошибки в группах похожих | Время на лист |
|---|---|---|---|---|---|
| 20 small, SVG | 1.000 | 1.000 | 0.999 | 0 % | ~3 с |
| 20 small, PDF | 0.999 | 1.000 | 0.998 | 0 % | ~3 с |
| large (31k примитивов, 596 экз.), SVG | 0.999 | 1.000 | 0.998 | 0 % | 18.4 с |

Критерии плана: F1 >= 0.92, ошибки внутри групп <= 5 %, small < 5 с, large < 60 с.
Все выполнены. Оставшиеся пропуски: зеркальный `bell` со стеной через него и один
`switch_s3` в PDF.

## 3. Растр и производительность

Растровая ветка: Sauvola, скелет, карта расстояний и направлений; гипотезы chamfer-поиском
(плотный проход по всем центрам на уменьшенном растре, перебор поз, уточнение); та же проверка
ICP и покрытием по пикселям скелета; маски пикселей вместо кусков.

| Набор | F1 | Precision | Recall | Время на лист |
|---|---|---|---|---|
| 5 small, чистый PNG 300 dpi | 0.872 | 0.915 | 0.832 | ~33 с |
| 5 small, «грязный» PNG (шум, размытие, поворот до 1°) | 0.838 | 0.859 | 0.817 | ~33 с |
| large PNG 7200x4800, 16 эталонов | 0.828 | | | 56 с |

Критерии плана: чистый PNG F1 >= 0.85, «грязный» >= 0.7 (выполнены). Бенчмарк фазы 6
(`tests/bench`): large вектор 19 с при пределе 60 с, растр 7200x4800 56 с при пределе 3 мин
(16 эталонов: столько классов в синтетике; оценка для 20 около 70 с).

Для растра введен отдельный порог принятия `raster_accept_score` = 0.9: по скелету плотная
тушь (стены, штриховка, текст) покрывает эталон легче, чем в векторе. На синтетике у верных
экземпляров покрытие не ниже 0.97 (10-й процентиль), у ложных медиана 0.90. Основная
оставшаяся ошибка растра: детекторы SD и CO (круг с разным текстом) путаются, так как текст
в растре не распознается.


## 4. Реальный чертеж

Данных из постановки (`data/real/`, JPG 7200x4800 и `instances_Train.json`) в репозитории и
на машине нет. Вместо них использован реальный векторный лист
`data/raw/electrical_plans/00_reference_camden_E1-1.pdf` (план освещения пожарной станции,
2592x1728 pt, 22 тыс. путей, 98 тыс. кусков после планаризации). Эталоны размечены вручную
по колонке SYMBOL таблицы светильников: 7 классов (A: светильник 2x4, B: накладной 4 фута,
C: настенный, D: high bay, E: вытяжной вентилятор, X: указатель выхода, Z: аварийный
светильник). Разметка: `docs/real/camden_queries.json` (только рамки эталонов).

Команда:

```bash
uv run symspot run data/raw/electrical_plans/00_reference_camden_E1-1.pdf --queries docs/real/camden_queries.json --out out/real/camden
```

Результат: 45 экземпляров на плане плюс 7 эталонов в легенде, за 10.3 с (чтение 0.8,
нормализация 1.0, таблица пар 3.3, проверка 3.3). Разметки экземпляров для этого листа нет,
поэтому полнота и точность оценены ручной сверкой оверлея с исходным листом:

| Класс | Найдено | На листе (ручной подсчет) |
|---|---|---|
| A | 17 | 17 |
| B | 3 | 3 |
| C | 5 | 5 |
| D | 8 | 8 |
| E | 2 | 2 |
| X | 5 | 5 |
| Z | 5 | 5 |

Ложных срабатываний при сверке не найдено. Символы, которых нет в таблице (динамики S,
пожарные F), не ищутся и не раскрашиваются. B и D в легенде отличаются только пропорциями
прямоугольника, путаницы между ними нет. Ручная сверка одного листа не заменяет разметку:
это оценка, а не измерение.

## 5. Известные проблемы

- Символы из одной строки текста с коротким отводом (выключатели S, S3, SD) держатся на
  тексте: в PDF рамка повернутого на 180° текста смещена относительно глифов, гипотеза от
  текста поэтому неточная, ее исправляет ICP с широким стартовым радиусом.
- Символ, через который проходит стена и который одновременно отражен и мал, иногда
  пропускается (единичные случаи на синтетике).
- Ключи пар чувствительны к тому, как исходный файл разбил линии символа на штрихи:
  разбиение отрезков на коллинеарные куски склеивается нормализацией, но, например,
  окружность, нарисованная двумя дугами разного радиуса, даст другой ключ.
- Текст в растре не распознается (OCR вне MVP): в растровом эталоне надпись входит в скелет
  как обычная тушь, строки не сравниваются, поэтому символы, различающиеся только текстом
  (SD и CO), в растре различаются хуже, чем в векторе.

## 6. Что делать дальше

1. Разметить реальный лист (или получить `instances_Train.json`) и измерить P/R по разметке.
2. Прогнать на остальных листах `data/raw/electrical_plans/` (легенды там на отдельных
   листах: нужна поддержка эталонов с другого листа того же комплекта).
3. Ускорить проверку гипотез (основная доля времени на large): ранний отказ по грубому
   покрытию до ICP, параллельность по эталонам.
4. Обучаемая ветка (SymPoint) и арбитр для неоднозначных случаев.
