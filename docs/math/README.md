Здесь лежит формальное описание алгоритма и ML-модели — первый пункт результата проекта.
Формулы пишем в Markdown с LaTeX (`$...$`, `$$...$$`): GitHub их отображает.

Что должно быть в итоге:

1. Формальная постановка задачи (черновик ниже).
2. Описание детерминированного алгоритма: представление чертежа, признаки, сопоставление, оценка

5. Оценка сложности и ограничения.

## Черновик постановки

Лист чертежа $P$ — набор векторных примитивов (отрезки, дуги, кривые Безье, текст) на плоскости.
Набор условных обозначений $\mathcal{T} = \{T_1, \dots, T_K\}$, каждое $T_k$ — тоже набор примитивов.

Допустимые преобразования $G$ — подобия плоскости: поворот на угол $\varphi$, масштаб $s$, отражение
$m \in \{0, 1\}$ и сдвиг $t$, то есть $g(x) = s R_\varphi M^m x + t$.

Нужно найти все пары $(k, g)$, для которых образ $g(T_k)$ совпадает с частью листа:

$$
d\bigl(g(T_k),\; P \cap \Omega_g\bigr) \le \varepsilon,
$$

где $\Omega_g$ — окрестность рамки $g(T_k)$, а $d$ — мера несходства (её нужно выбрать: например,
расстояние Хаусдорфа или Шамфера между примитивами).

Ответ сервиса — список рамок $\{x, y, w, h\}$ с идентификатором обозначения, углом $\varphi$,
флагом отражения $m$ и оценкой сходства $\text{score} \in [0, 1]$ (см. `Detection` в
`backend/app/models.py`).
