# Отчёт о качестве

Отчёт с анализом качества работы алгоритма и предложениями по его улучшению — третий критерий оценки
проекта. Графики и таблицы для него кладём в `figures/`.

## Как измеряем

- Эталон — разметка в формате [samples/ground_truth.json](../samples/ground_truth.json) и наборы из
  [datasets/](../datasets/).
- Найденный экземпляр засчитывается, если совпадает тип обозначения и пересечение рамок
  с эталонной (IoU) не меньше порога, по умолчанию 0,5.
- Метрики: precision, recall, F1 — общие и по каждому типу обозначения; отдельно для повёрнутых,
  зеркальных и масштабированных экземпляров; время поиска на лист.
- Экземпляры в таблице условных обозначений (`legend: true`) считаем отдельно.

## Как посчитать

Скрипт [scripts/evaluate.py](../scripts/evaluate.py), код метрик — `backend/app/evaluation/`.

```sh
backend/.venv/bin/python scripts/evaluate.py                       # алгоритм сервиса (сейчас stub) на samples/
backend/.venv/bin/python scripts/evaluate.py --detector my         # свой алгоритм из DETECTORS
backend/.venv/bin/python scripts/evaluate.py --pred answers.json   # готовые ответы, без запуска алгоритма
backend/.venv/bin/python scripts/evaluate.py --simulate            # «шумная» разметка вместо алгоритма
backend/.venv/bin/python scripts/evaluate.py --gt other/gt.json --drawings other/  # другой датасет
backend/.venv/bin/python scripts/evaluate.py --gt datasets/electrical-plans/annotations/*.json --pred results.json
```

Разметка (`--gt`) — наш JSON или COCO, можно несколько файлов сразу. Ответы (`--pred`) — наш JSON
или COCO results (`[{"image_id", "category_id", "bbox", "score"}]`). Подробнее о форматах —
[datasets/README.md](../datasets/README.md).

Параметры: `--iou 0.5` — порог IoU, `--score-threshold 0` — отбросить неуверенные ответы,
`--include-legend` — оценивать и таблицу условных обозначений.

Образцом для поиска служит первый экземпляр каждого обозначения в таблице условных обозначений
(`legend: true`) того же чертежа. Сами экземпляры в таблице по умолчанию не оцениваются.

Результат — в `report/results/<алгоритм>/`:

| Файл | Что внутри |
|---|---|
| `summary.md` | сводная таблица для отчёта |
| `metrics.json` | все метрики, PR-кривая и список ошибок (`errors`: пропуски и ложные срабатывания) |
| `pr_curve.csv`, `pr_curve.svg` | PR-кривая |
| `predictions.json` | ответы алгоритма — можно оценить заново с другими порогами через `--pred` |

Что считается:

| Метрика | Как |
|---|---|
| IoU | средний IoU попаданий |
| Precision, Recall, F1 | micro (все обозначения вместе), macro (среднее по обозначениям) и по каждому |
| PR-кривая, AP | перебор порога уверенности; AP — площадь под огибающей кривой, mAP — среднее AP по обозначениям |
| Время на чертёж | среднее, медиана, максимум; среднее на лист |

Сопоставление — как в COCO: ответы по убыванию уверенности забирают свободный эталон того же типа
на том же листе с наибольшим IoU. Повторный ответ на тот же эталон — ложное срабатывание.

Пока не сделано: Drop-off Rate по сложности (Easy / Medium / Hard) и метрики по штрихам.
