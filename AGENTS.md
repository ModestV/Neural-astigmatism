# AGENTS.md

Инструкции для ИИ-ассистентов (Claude Code, Cursor, Codex, ChatGPT и других), которые работают в этом
репозитории. Это единственный источник правил: `CLAUDE.md` подключает этот файл. Если меняете структуру
репозитория или договорённости команды, обновите `AGENTS.md` в том же коммите.

## Проект

Командный студенческий проект «Поиск на чертежах условных обозначений из заданного набора».
Полная постановка — [docs/task.md](docs/task.md).

Цель — алгоритм и модель для точной детекции графических условных обозначений, заданных набором
геометрических шаблонов, на векторных чертежах (DWG, PDF, SVG). Ожидаемое решение — детерминированный
алгоритм (сопоставление геометрии, RANSAC и т. п.) плюс оракул или эвристика на основе ML-модели.

Что сдаём:
1. Математическое описание алгоритма и модели с обзором литературы → `docs/math/`, `docs/literature/`.
2. Прототип на Python или Julia → `backend/app/detection/`.
3. Обучающий набор данных, если нужна ML-модель → `datasets/`.
4. Отчёт о качестве (precision, recall, F1) и предложения по улучшению → `report/`.

## Текущее состояние

Работает веб-сервис: загрузка и просмотр чертежей, библиотека образцов, поиск, история запусков.
**Алгоритма поиска пока нет**: вместо него заглушка `backend/app/detection/stub.py`, которая находит только
сам образец. Страница «Оценка качества» — тоже заглушка. План работ — в разделе «Что дальше» в `README.md`.

## Карта репозитория

```
backend/              FastAPI, Python 3.12+
  app/converters.py   PDF / SVG / DXF / DWG → постраничные SVG + миниатюры
  app/detection/      алгоритмы поиска: интерфейс Detector (base.py), заглушка (stub.py)
  app/models.py       модели данных, они же формат JSON в data/
  app/routers/        обработчики API
  tests/              pytest
frontend/             React + TypeScript + Vite; src/api/types.ts повторяет схемы бэкенда вручную
samples/              тестовые чертежи и эталонная разметка ground_truth.json
scripts/              make_samples.py (генератор samples/), dev.sh (запуск бэкенда и фронтенда)
docs/                 постановка, обзор литературы, математика, архитектура
datasets/             обучающие наборы (большие — по ссылке, не в git)
experiments/<ник>/    личные черновики участников
notebooks/            общие ноутбуки
report/               отчёт о качестве и графики
data/                 рабочие данные сервиса — создаётся сам, НЕ в git
```

Устройство сервиса, координаты и подключение алгоритма — [docs/architecture.md](docs/architecture.md).

## Команды

```bash
cd backend && python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements-dev.txt
cd backend && pytest                            # тесты бэкенда
cd frontend && npm install && npm run lint && npm run build
./scripts/dev.sh                                # бэкенд :8000 + фронтенд :5173
```

Перед коммитом запускайте `pytest` и, если менялся фронтенд, `npm run lint && npm run build`.
То же проверяет CI.

## Соглашения

- Комментарии, docstring и документация — на русском. Имена в коде — на английском.
- Сообщения коммитов — на английском, в повелительном наклонении: `Add RANSAC detector`.
- Python: ruff, длина строки 100, аннотации типов у публичных функций. Модели данных — pydantic.
- Все рамки — `{x, y, w, h}` в единицах страницы, начало в левом верхнем углу, ось Y вниз.
  Не меняйте это без обновления фронтенда и `docs/architecture.md`.
- Новый алгоритм — отдельный класс-наследник `Detector` в `backend/app/detection/`, зарегистрированный
  в `DETECTORS`. Заглушку не удаляйте: на ней держатся тесты.
- Меняете схемы API (`backend/app/schemas.py`, `models.py`) — обновите `frontend/src/api/types.ts`.
- Тяжёлые библиотеки (torch, opencv, juliacall) импортируйте внутри модуля своего алгоритма,
  чтобы сервис и тесты работали без них.
- Новые зависимости добавляйте с точной версией в `backend/requirements.txt` и сначала обсудите с командой.

## Тесты

- Каждый новый модуль — с тестами в `backend/tests/`.
- Тесты быстрые и без интернета: используют чертежи из `samples/` или генерируют свои.
- Качество алгоритма меряем отдельно (отчёт в `report/`), а не порогами в unit-тестах.

## Командная работа

- Задачу делаем в ветке `<ник>/<кратко-что-делаю>`, в `main` попадаем через Pull Request.
- Личные черновики — в `experiments/<ник>/`. Чужие папки, ветки и эксперименты не трогаем без просьбы.

## Чего не коммитить

`data/`, `.venv/`, `node_modules/`, `frontend/dist/`, `.env`, веса моделей (`*.pt`, `*.onnx`,
`*.safetensors`), большие чертежи и наборы данных. Публикуем их отдельно и даём ссылку.

## Термины

- **Условное обозначение (символ)** — графический знак из заданного набора: розетка, выключатель,
  светильник и т. п.
- **Образец (шаблон)** — рамка на листе вокруг эталонного обозначения; хранится в библиотеке.
- **Symbol spotting** — английское название задачи поиска обозначений на чертежах.
- **Таблица условных обозначений (легенда)** — блок на листе с образцами и расшифровкой; экземпляры
  в ней размечены флагом `legend`.
- **RANSAC** — оценка преобразования по случайным выборкам соответствий с отбором согласованных точек.

Исследование ORB+RANSAC, SIFT+RANSAC и Template Matching участника vozderjus размещается в
`experiments/vozderjus/symbol_matching/`; исходные PDF (`drawings/`), кэш (`cache/`) и результаты
(`results/`) локальные и исключены из Git правилами внутри папки исследования.
