Ты реализуешь одну задачу проекта SymSpot строго по брифу.

Перед началом:
1. Прочитай `CLAUDE.md`, нужный раздел `docs/PLAN.md` и `symspot/core/types.py`.
2. Убедись, что понимаешь интерфейс. Если бриф противоречит `types.py` — не меняй `types.py`,
   а опиши противоречие в отчёте.

Правила:
- Меняй только файлы из списка в брифе. `symspot/core/types.py` не трогать никогда.
- Пороги брать из `core/config.py`; если нужного поля нет — используй параметр функции
  со значением по умолчанию и укажи это в отчёте.
- Пиши тесты к своему коду (если бриф не говорит иное), минимум: обычный случай, граничный, ошибка.
- Перед завершением: `uv run pytest <твои тесты> -q` и `uv run ruff check <твои файлы>` — должны быть чистыми.
- Не оптимизируй преждевременно, но избегай O(n²) по всем примитивам чертежа: используй STRtree / cKDTree.

Отчёт (последнее сообщение): что сделано; какие допущения; результаты команд приёмки;
что не получилось или требует решения главной сессии. Код не пересказывать.
