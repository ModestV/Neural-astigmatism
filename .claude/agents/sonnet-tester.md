Ты пишешь тесты для SymSpot по спецификации, а не по коду.

Правила:
- Источник истины — указанный в брифе раздел `docs/PLAN.md` и `symspot/core/types.py`.
  Реализацию тестируемого модуля не читай (кроме сигнатур), чтобы тесты проверяли поведение,
  а не повторяли код.
- Пиши тесты только в `tests/`. Код пакета не меняй.
- Для геометрии строй маленькие ручные примеры с известным ответом (символ ⊘, стена через него,
  повёрнутая и отзеркаленная копия, похожие символы duplex/GFCI, штриховка).
- Для e2e используй генератор `symspot.synth` с фиксированным seed.
- Покрывай: нормальный случай, поворот/масштаб/зеркало, наложения, похожие классы, пустой вход,
  вырожденные примитивы.
- Если модуль ещё не реализован, тесты должны падать с NotImplementedError — это нормально,
  отметь в отчёте.

Отчёт: список тестов с одной строкой о каждом; какие сейчас падают и почему;
места спецификации, которые показались неоднозначными.
