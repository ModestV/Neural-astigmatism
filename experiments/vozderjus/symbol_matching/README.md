# Сравнение алгоритмов поиска условных обозначений

Автономное исследование vozderjus: Template Matching, ORB+RANSAC и SIFT+RANSAC.
Код пока не подключён к веб-сервису. Набор PDF, кэш и результаты хранятся локально.

## Структура

- `run_benchmark.py` — единая точка запуска.
- `models.py` — проверка входных параметров и конфигурации.
- `pdf_io.py` — инвентаризация, растеризация и кэш страниц.
- `evaluation.py` — объектные Precision, Recall, F1 и исключение легенды.
- `algorithms/` — Template Matching, ORB/SIFT с RANSAC, общая геометрия.
- `drawings/чертежи/` — добавленные пользователем PDF; не в Git.
- `annotations/` — конфигурации образцов и эталонная разметка, можно хранить в Git.
- `cache/` — воспроизводимые растровые страницы; не в Git.
- `results/` — отдельный каталог на каждый запуск; не в Git.

## Окружение

Из корня репозитория, в существующем окружении бэкенда:

```sh
backend/.venv/bin/python -m pip install -r experiments/vozderjus/symbol_matching/requirements.txt
```

OpenCV и NumPy закреплены в `backend/requirements.txt`, как предусмотрено `AGENTS.md`.
Тяжёлые библиотеки импортируются только внутри функций исследования.
Конфигурации проверяются через Pydantic. На этапе исследования веб-сервис запускать не нужно.

Все команды ниже выполняются из корня репозитория. По умолчанию каталоги данных определяются
относительно самого скрипта: запуск из другой папки не меняет расположение `drawings`, `cache`, `results`.
Явные относительные пути в аргументах командной строки разрешаются относительно текущего каталога.

## 1. Проверить набор

```sh
backend/.venv/bin/python experiments/vozderjus/symbol_matching/run_benchmark.py inspect
```

Скрипт рекурсивно ищет PDF, в том числе в `drawings/чертежи/`, и сохраняет `inventory.json`:
число страниц, размеры, поворот, число векторных путей, ресурсы изображений и SHA256.
Наличие векторных путей не означает, что вся страница векторная.

## 2. Получить изображение страницы

```sh
backend/.venv/bin/python experiments/vozderjus/symbol_matching/run_benchmark.py prepare \
  --file 'чертежи/01_riga_lighting.pdf' --page 1 --dpi 150
```

Появятся `page.png` и `page.json` с размером и масштабом. Кэш учитывает содержимое PDF,
номер страницы, DPI и версию PyMuPDF. Изменение файла или DPI меняет ключ кэша.
Ограничение размера растра по умолчанию 40 миллионов пикселей. Для крупных листов сначала уменьшите DPI.

## 3. Выбрать свой образец

```sh
backend/.venv/bin/python experiments/vozderjus/symbol_matching/run_benchmark.py select-template \
  --file 'чертежи/01_riga_lighting.pdf' --symbol my_symbol \
  --config-out experiments/vozderjus/symbol_matching/annotations/my_query.json
```

Откроется окно выбора прямоугольника: выделить мышью, подтвердить Enter. Отмена — Esc.
Окно показывает уменьшенную страницу, поэтому для мелкого символа точнее задать рамку явно:
`--bbox X Y W H`. Координаты — пункты PDF, НЕ пиксели, относительно видимой страницы с учётом поворота.
Существующая конфигурация не перезаписывается.

Сгенерированная конфигурация ищет на той же странице; список `targets` можно дополнить другими PDF.
Исходная область образца автоматически исключается из поиска и оценки на той же странице.
В `annotations/riga_demo.json` уже есть один вручную выбранный образец из легенды для проверки запуска.
Его семантический класс в конфигурации относится только к выбранному начертанию;
поиск других вариантов начертания того же класса не гарантируется.

## 4. Запустить все методы

```sh
backend/.venv/bin/python experiments/vozderjus/symbol_matching/run_benchmark.py run \
  --config experiments/vozderjus/symbol_matching/annotations/riga_demo.json \
  --algorithms template orb sift --dpi 150 --scales 1 --angles 0 90 180 270
```

Пороги стартовые, они НЕ подобраны на тестовом наборе. Допустимы другие масштабы, например
`--scales 0.75 1 1.25`. Для ORB/SIFT геометрический масштаб должен попадать в окрестность одного
из заданных масштабов (`--scale-tolerance 0.15`), угол — в окрестность заданного угла
(`--angle-tolerance 10`, градусы). Template Matching использует дискретный перебор точно заданных
масштабов и углов. Это различие записывается в параметрах; полной эквивалентности нет.
Зеркальные экземпляры в первой версии не поддерживаются.

По умолчанию страница переводится в grayscale без бинаризации:

- Template Matching — инверсия яркости, `TM_CCORR_NORMED`, перебор преобразований и NMS.
  Это обычный корреляционный baseline, не clutter-tolerant метод Rezvanifar.
- ORB — `ORB_create`, до 5000 признаков, `edgeThreshold=7`, `patchSize=15`, Hamming matcher.
- SIFT — `SIFT_create`, до 5000 признаков, L2 matcher.
- Для ORB/SIFT: соответствия от точек страницы к точкам образца, ratio test, последовательный
  RANSAC `estimateAffinePartial2D` (перенос, поворот, равномерный масштаб), проверка масштаба,
  угла, пространственного разброса inliers, доли inliers в рамке и NMS.
  После проверки гипотезы её inliers удаляются и поиск продолжается.
  Это базовая эвристика нескольких экземпляров; её полнота не гарантируется при сильной
  неоднозначности признаков. Глобальный лимит признаков также может пропускать мелкие символы.

Если ключевых точек недостаточно, в JSON появляется `insufficient_keypoints`.
Число inliers не является метрикой качества поиска. `score` методов имеет разный смысл:
корреляция для Template Matching, локальная доля inliers для ORB/SIFT. Их нельзя сравнивать напрямую.

## Результаты

Каждый запуск создаёт отдельную папку с UTC-временем и уникальным суффиксом:

- `manifest.json` — входная конфигурация, параметры, версии библиотек, SHA256 кода.
- `template_N.png` — фактически использованный образец.
- `NNN_алгоритм.json` — рамки в единицах PDF, диагностика, SHA256 PDF и метрики.
- `NNN_алгоритм.png` — обнаружения красным, эталонные рамки синим.
- `metrics.csv` — по одной строке на страницу и алгоритм.
- `summary.json` — суммарные TP/FP/FN и micro-метрики по размеченным страницам.
- `status.json` — `running`, `complete` или `failed`.

Время подготовки страницы отделено от `search_seconds`. Поиск включает выделение признаков,
перебор преобразований, RANSAC, NMS и фильтрацию исключаемых областей.
Запись изображений и расчёт метрик в него не входят.
Порядок алгоритмов фиксирован, один поток OpenCV и фиксированный seed. Для исследования скорости
нужны отдельные повторные замеры, прогрев и перестановка порядка; единичный запуск лишь диагностический.

## Эталонная разметка и метрики

`ground_truth: null` — страница НЕ размечена: Precision, Recall, F1 остаются `null`.
`ground_truth: []` — страница полностью проверена, искомых объектов на ней нет.
Нельзя размечать лишь часть объектов и трактовать остальные обнаружения как ложные.

В каждый объект `targets` можно добавить эталон:

```json
"ground_truth": [
  {
    "symbol": "my_symbol",
    "bbox": {"x": 100, "y": 200, "w": 20, "h": 15},
    "legend": false
  }
]
```

Числа выше — пример структуры, НЕ разметка реального чертежа.
`symbol` должен соответствовать классу в `templates`. По умолчанию требуется совпадение класса и
IoU >= 0.5. Предсказания упорядочиваются по score внутри метода и сопоставляются с ещё не занятыми
эталонами по максимальному IoU. Повторные обнаружения одного объекта становятся FP.

Легенда (`legend: true`) по умолчанию исключается, `--include-legend` включает её в оценку.
`ignore_regions` исключает обнаружения и эталонные объекты по попаданию центра рамки в область.
Для точного исключения всей легенды укажите её полную рамку в `ignore_regions`.
Область исходного образца исключается автоматически даже с `--include-legend`.
На страницах без объектов Recall не определён; без предсказаний Precision не определён.
Такие значения остаются `null`; F1 считается по 2TP/(2TP+FP+FN), если знаменатель ненулевой.

Эталонные bbox используют `{x, y, w, h}` в координатах отображаемой страницы. Старый формат
`samples/ground_truth.json` с массивами bbox напрямую пока не импортируется.

## Проверки

```sh
cd backend
.venv/bin/python -m pytest tests/test_symbol_matching_experiment.py
```

Проверки не требуют сети и не зависят от PDF пользователя. Проверяются поворот страницы и кэш,
несколько экземпляров, объектное сопоставление, исключение легенды и отсутствие разметки.
При отсутствии OpenCV алгоритмические проверки пропускаются, а API сервиса продолжает работать.
